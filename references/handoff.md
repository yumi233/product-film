# 交接：在 Claude 桌面端、Claude CLI、Codex 之间换着做

一部片子要做很多小时，经常换工具（额度用完、换模型、换电脑）。交接靠三样东西：**一份交接文件、一个状态快照、一把执行者锁**。

## 一、交接文件（项目里只维护一份）

- 位置：项目的文稿目录里，固定文件名 `<项目名>视频_交接.md`（例：`03内容规划/节序视频_…/节序视频_交接.md`）。只更新这一份，不按日期另起新文件；文件开头写最后更新时间和更新人。
- 固定六块（顺序不变）：
  1. **先读什么**：本文件 → 定稿方案 → 文件索引 → 本技能 SKILL.md。
  2. **用户已经批准的**（不要再问）：定稿的方案、已定稿的幕、长期授权（例如「洗完图核对过就直接生成，不用再审」）。写清日期和原话要点。
  3. **必须遵守的规则**：用户反复强调过的（时长、机器、出图方式、风格、不贴图、声音、文件位置、账号安全）。
  4. **当前状态**：由 `handoff.py status --write` 自动生成，放在 `<!-- handoff:status:start -->` 和 `<!-- handoff:status:end -->` 之间，不手写。
  5. **中断后怎么接上**：每类任务的恢复命令（RunningHub `--fetch`、批次重跑会跳过已有、出图和洗图重跑会跳过已有）。
  6. **接下来按什么顺序做** + 余额 + 每批要汇报什么。

## 二、什么时候更新

每到一个节点就更新，不要等到要交接时才补：
- 一批视频 / 一批关键帧 / 一批洗图跑完；
- 一幕粗剪定稿；
- 用户改了规则、给了新授权、否掉了什么；
- 用户说「更新交接」「我要换工具」「额度快没了」。

更新做法：先跑 `python3 scripts/handoff.py status <项目> --write <交接文件>` 刷新第四块，再手动改其余几块里变化的地方。

## 三、执行者锁：同一时间只有一个 agent 动手

浏览器（ChatGPT / Gemini 网页）同一时间只能有一个人在点；RunningHub 一个账号同一时间只跑一个任务；本机 TTS 一次只能跑一个。两个 agent 同时干活会互相抢窗口、排队、把用户电脑拖慢。

```bash
python3 scripts/handoff.py who     <项目>              # 先看谁在做
python3 scripts/handoff.py claim   <项目> "Codex"       # 接手前占住
python3 scripts/handoff.py release <项目> "Claude桌面"  # 交出前释放
```

- 锁是项目根目录下的 `.product-film-driver` 文件，只是提醒，不强制。**开始任何生成任务前先 `who`。**
- 别人占着锁但确认对方已经停了（会话关掉、额度用完），才可以 `claim --force`。
- 只读的事（看日志、写方案、审图、写剪辑配置）不需要锁，可以多个 agent 同时做。

## 四、交出方（要离开的 agent）做什么

1. 等当前这批跑完；来不及就确认日志和 RunningHub 任务号都已落盘（`rh_tasks.log`）。
2. `handoff.py status --write` 刷新状态，补全交接文件其余几块。
3. `bsk session list`，停掉自己开的浏览器会话。
4. `handoff.py release`。
5. 告诉用户：交接文件位置、给下一个 agent 的那句话（见下）。

## 五、接手方（新来的 agent）做什么

1. `handoff.py who`；没人占用就 `claim`。
2. 读交接文件，按「先读什么」读完。
3. `handoff.py status` 看实际状态，和交接文件对一遍。
4. 把中断的任务接上：RunningHub 未下载的任务号用 `rh_run.py --fetch`；批次和出图、洗图直接重跑同一份清单（已有输出会跳过）。
5. 按「接下来」继续；每批结束汇报，并更新交接文件。

给接手 agent 的固定一句话：

```text
接手<项目名>视频：先读 <交接文件路径>，用 handoff.py who/claim 占住执行者锁，检查正在跑的任务并接上，然后按里面的规则和顺序继续，每批结束汇报生成了什么、花了多少 RH 币，并更新交接文件。
```

## 六、在各个终端里打开

| 工具 | 命令 |
|---|---|
| Claude 桌面端 | 新建会话，选项目文件夹，发上面那句话 |
| Claude CLI，接着原会话 | `cd <项目> && claude --resume <会话编号>` |
| Claude CLI，带着上下文另开一份 | `cd <项目> && claude --resume <会话编号> --fork-session`（桌面端还开着时用这个，避免两边写同一个会话） |
| Claude CLI，从列表挑 | `cd <项目> && claude --resume` |
| Codex | `cd <项目> && codex -m <模型> -c model_reasoning_effort=xhigh "<上面那句话>"` |

- 会话按「当前目录」存放：一定先 `cd` 到项目目录。
- 后台任务属于启动它的那个会话：会话关掉后可能被中断，所以交出前要确认任务号已落盘。
- 很长的对话，接手时会被压缩；以交接文件为准，不要依赖对话记录里的细节。
