# RunningHub 接入

## 账号与 key
- 用户用的是**会员（消费）key**，扣 RH 币。它可以跑工作流：`/task/openapi/upload`、`/task/openapi/create`、`/task/openapi/status`、`/task/openapi/outputs`。
- **标准模型 API**（`/openapi/v2/...`，比如万相、可灵、TTS、作曲）只能用企业共享 key 调用，会员 key 会返回错误 1014。所以本技能只走工作流。
- key 存在环境变量 `RUNNINGHUB_API_KEY` 里，写在 `~/.zshrc`。运行时要用 `zsh -ic "python3 ..."` 才能读到。**不要让用户把 key 贴到聊天里，也不要打印 key。**
- 查余额：`rh_run.py --check`，返回 RH 币、钱包余额和正在运行的任务数。
- 钱包余额为 0 时，网页画布上的官方 H3 用不了（768P、6 秒一条扣 ¥2.88）。要花钱包里的钱，必须先问用户。

## 工作流：AITUDOU MiniMax H3 ReferenceToVideo（2113173574050729986）
| 节点 | 作用 | 字段 |
|---|---|---|
| 88 / 84 / 86 / 87 | 参考图 1–4（LoadImage） | image |
| 94 | 提示词（Text） | text |
| 85 | 视频时长，单位秒（Float，默认 13.5） | value |
| 63 | 最终画面大小，单位百万像素（ResolutionSelector，固定 16:9，默认 0.4） | megapixels |
| 111 | 二次采样器的首采缩放比例（SelfLiftH3Sampler，默认 0.5） | lowres_scale |

**分辨率和费用（实测）**

| megapixels / lowres | 输出 | 费用 | 用时 |
|---|---|---|---|
| 1.0 / 0.5 | 1376×768 | 约 50 币 | 约 4 分钟 |
| 2.07 / 0.66 | 1952×1120 | 约 12.5 币/秒：8 秒约 100、10 秒约 133、15 秒约 185 | 8 秒约 8 分钟 |
| **3.0 / 0.66，6 秒（v16 默认）** | **约 2368×1344** | **约 110–130 币/条** | **约 9–10 分钟** |

- **现在的默认：`--secs 6 --mp 3.0 --mp-fallback 2.5,2.07`**。剪辑里一个镜头只用 3–5 秒，6 秒足够；秒数降下来，显存够跑 3.0 MP，画面明显比 1952×1120 清楚。OOM 时自动降到 2.5、2.07（失败不扣费）。曾因 OOM 降到 1.2 MP（1504×832）的片子在成片里明显糊，不要再用。
- **参考图最多 5 张**（起始帧 + 4 张产品渲染图），多了会 OOM；`rh_run.py` 超过 5 张会截断并警告，`qc.py refs jobs.json` 可预先检查。起始帧里产品已经清楚时，只给起始帧就够。
- 想要稳定运镜，提示词加：`Camera on a stabilised dolly: perfectly smooth, constant slow speed, no shake, no jitter, no sudden moves.` H3 偶尔输出帧间快慢交替的抖动片，出来后用 `qc.py jitter` 测，变异系数 >0.6 或有突跳的重抽。
- 1952×1120 的比例是 1.743，比 16:9 略窄。cut.py 会先缩放到 1920 宽，再裁成 1080 高，不会把画面压扁。
- 优先让视频模型生成环境声/同步音效，禁止旁白、对白、唱歌和配乐；`rh_run.py`自动追加声音约束。实际有无音轨及是否串人声，仍须输出后核查。原音轨核听无说话声后由`cut.py`保留（`source_audio: "verified_ambience"`），旁白另轨后期合成。
- 时长节点 85 默认 13.5，**15 秒可用**（`--secs 15`）。
- **不支持真正的首尾帧**：给两张参考图时，开头常常不是第一张、结尾也不一定停在第二张。现在的做法是只给一张起始帧，用剪辑保证流畅（见 shot-script.md）。

另一个工作流 Work-Fisher（2109735475824123905）是单次采样、只有两张参考图、0.8 MP，其余功能组都被禁用了，API 打不开。没有理由用它。

## 并发与报错
- **多账号并行**：每个账号同时只能跑 1 个任务。用户有第二个账号时，让用户自己在终端运行下面这行把 key 写进 `~/.zshrc`（输入不回显，不经过聊天）：
  `read -s "k?粘贴第二个 RunningHub key 后回车: " && echo "export RUNNINGHUB_API_KEY_2=\"$k\"" >> ~/.zshrc && unset k && echo 已保存`
  然后 `rh_run.py --check --key-env RUNNINGHUB_API_KEY_2` 只看余额确认可用；两个账号各自一条队列（`--key-env` 指定），速度约翻倍。不要让两个队列跑同一条镜头。
- 单账号内：再提交会返回 421 `TASK_QUEUE_MAXED`。rh_run.py 遇到会每 30 秒重试一次，所以批量任务只能按顺序跑。
- 状态每 20 秒查一次，一条通常 8–10 分钟。批量任务放到后台跑，等完成通知，不要守着轮询。
- 跑完会打印 `SAVED <path> coins <n>`。把每条的币数加起来，汇报给用户。
- **一定用 `python3 -u` 并把输出直接写到日志文件**（`> videos/xx.log 2>&1`）。不要接 `| grep`：管道会缓冲，进程被杀时任务编号一起丢，钱扣了视频取不回（RunningHub 网页的个人中心看不到 API 任务）。
- 每个任务一创建，编号就写进 `<out-dir>/rh_tasks.log`。会话中断后：`python3 rh_run.py --fetch <任务编号> --name <名字> --out-dir <目录>` 取回。
- **失败不扣费**：状态 FAILED（比如服务器 `torch.OutOfMemoryError`）时余额不变，直接重跑即可。

## 其他可以用 RH 币跑的应用（会员 key 可用；标准模型 API 如 MiniMax 语音/作曲返回 1014，不能用）
- **旁白（云端，不占用户电脑）**：
  1. `Qwen3 TTS 声音设计`（webappId 2014603342701404161）：用一句话描述音色出参考音。**节点 7、6 的 select 要设 2（手写）**，设 1 是随机音色、随机台词。
  2. `声音克隆 IndexTTS2.5`（webappId 2113135025851035650）：节点 1 上传参考音，2 文本，8 语速（1.05），49 情绪模式 2 + 节点 6 文字描述（如「平静温和，娓娓道来」），33 强度 0.6。**一句一个任务**，每句出来用 ASR 回读核对，断句不清的改写后重做。
- **配乐（只作退路，优先可商用曲库，见 audio.md）**：`Suno V5.5 音频生成`（2080197607661592577）、`【歌曲生成】suno v5.5`（2062762738333605890）实测都返回 805「工作流运行失败」；`Ace-step 纯音乐`（2030661316926509058，节点 14 时长、16 风格描述）能出 4 分钟，但低频重、配器满，不经试听不能用。
- `RH Suno_Single`（1972977443998928898）：输出带人声的歌，先问用户。
- 查应用的节点：`python3 ~/.claude/skills/runninghub/scripts/runninghub_app.py --info <webappId>`。

## Plus 大显存（48G）
- `rh_run.py --plus` 在创建任务时加 `instanceType: "plus"`，对应网页上的「Lite/Plus 运行」。
- 什么时候用：15 秒长镜、2.07 MP 高分辨率，或者默认机器报 `torch.OutOfMemoryError` 时。
- 代价（实测 2026-10-27）：15 秒 2.07 MP 一条 **508 币、用时 21 分钟**，约为默认机器同等时长的 2.7 倍，而且并不更快。用户认为太贵，**默认不用**，只在用户明确同意时用。
- 实测默认机器：10 秒稳定（约 133 币）；15 秒连续两次 OutOfMemory（失败不扣费）。现在默认 6 秒 3.0 MP。
- 失败不扣费；任务编号同样记进 `rh_tasks.log`。
