# 声音、字幕、片名

## 旁白

### 怎么写（用户两次说「不像人写的」「尬」之后定下的）
- **不写口号和对仗**：「竹有节，茶有序」「器物在变，围坐的方式没有变」这类像作文，不像人说话。
- **讲一个具体的故事**：一个讲述者（比如画中那位主人，也是片尾的真人主人），一件事（一个朋友晚上来喝茶），从开头讲到结尾。
- **只说具体的事**：烧水、坐哪、问起一只旧盏、天黑开灯、起风。不说「设计」「功能」「传承」。产品的好处让画面去展示。
- **旁白指给观众看画面正在发生的事**（「画里有个小孩，蹲在地上扇炉子」），不重复画面，也不解释画面。
- **首尾呼应，最后一句是一个画面**，不是一个道理。例：开头「我先把水烧上了」，结尾「我说好，水给你烧着」。
- 句子短、口语，能直接说出口；全片 12–14 句、约 50 秒。
- 需要「设计者本人」讲时，请用户给一段真实回忆，不替用户编。
- 有 human-first-article 技能时，用它过一遍文案。

### 先确认旁白从哪里来
旁白独立于视频生成，在剪辑阶段合成。视频模型优先生成环境音效，不读旁白、不让人物说话，也不承担配乐。

1. 用户提供最终旁白录音：直接导入，不依赖Qwen3。支持WAV、MP3、M4A、FLAC，整段或分句均可；同时索要对应文稿。
2. 用户已有并选择本机Qwen3：用`vo.py`单独生成，再导入。
3. 用户明确不要旁白：保持无旁白。缺音频时可做标注清楚的画面粗剪，但不声称配音已完成。

**没有Qwen3时，直接这样向用户说明**：
> 请提供这版文稿的最终旁白录音，WAV、MP3、M4A或FLAC都可以。整段录音或按N01、N02分句都能用，最好同时附上对应文字；我会按录音时长调整画面与字幕，再把旁白和视频环境声合成。没有本机Qwen3也能继续，不必为此安装模型。

录音尽量无背景音乐、少混响，句首句尾留一点空白。先提供最终文稿、编号和预计停顿，方便用户录制。声音克隆的短参考样本不能当作最终旁白；用户未选择TTS时，不只索要音色样本。

### 导入用户录音（不需要Qwen3）
`cut.py`配置示例，路径相对于配置文件：
```json
{
  "source_audio": "mute",
  "vo": {
    "tempo": 1.0,
    "lines": [
      {"id": "N01", "path": "audio/user/N01.m4a", "seg": 0, "at": 0.6,
       "zh": "那天下午，我在看一幅旧画。", "en": "That afternoon, I was looking at an old painting."}
    ]
  }
}
```
整段音频也可作为一条`path`导入；需要逐句字幕时，应先按文稿对齐或分句。旧的`vo.dir`加`id.wav`格式继续支持。默认不改用户录音语速，使用1.0；本项目原0.92配置仍保留。

文件不存在会在视频编码前提示提供录音；录音超出时间轴会报错，不静默截断。提供音频后测时长、核听文字、检查句末与字幕，必要时调整画面停留。没有ASR时人工核听，不把下载模型当作交付前提。

### 可选：本机Qwen3单独配音
用户选择本机TTS、且模型已就绪时使用，不启动安装或下载流程。
```bash
VO_REF=audio/参考.wav VO_REF_TEXT="参考录音原文" python3 -u scripts/vo.py lines.json audio/vo/
```
同一片优先使用同一声音克隆，逐句核听文字与音色。有ASR时辅助核对；音高范围以该说话人为基准，不把男声90–120Hz当作所有人的合格线。TTS与ASR一次只跑一个。macOS say仅在用户明确接受的占位稿中使用，不代替用户选定的最终声音。

### 可选：RunningHub 云端配音（不占用户电脑）
用户嫌本机 Qwen3 音色不好或电脑卡时用，扣 RH 币（每句几个币）。
1. 先写好音色描述（例：「五十岁左右的中国男性纪录片讲述人，嗓音低沉温润，语速平稳偏慢，不是播音腔」），用「Qwen3 TTS 声音设计」应用出一段 15 秒左右的参考音；节点 select 必须设 2（手写），设 1 会得到随机音色和随机台词。给用户听过再往下。
2. 用「IndexTTS2.5」应用拿这段参考音逐句克隆，**一句一个任务**，文件名用句号编号。
3. 每句用 ASR 回读：同音字可以接受，断句错的（例「撑开围面」被读成「撑开，为面」）改写文稿后重做；容易误听的词换说法（「杆节」→「杆件和节点」）。
应用编号和节点见 runninghub.md。

## 配乐
**用户反馈过「背景音乐不对」「很吵」之后定下的做法：**
1. **先找可商用的真乐器曲给用户挑**：Pixabay 音乐（Pixabay Content License，可商用、免署名）搜 guqin / xiao flute / chinese zither meditation 等，列 3–5 首带试听链接、时长和一句评价，推荐一首或两首搭配（例：第一幕用箫曲开头的安静段，器物段起交给琴曲）。用户点头后再下载。
2. AI 作曲只作退路：RunningHub 上 Suno 应用实测失败，ACE-Step 能出但低频重、配器满；任何 AI 曲都要完整听过、看过频谱再用。`score.py` 的程序合成古琴音色单薄，只适合占位。
3. **先定曲，再剪**：`python3 scripts/music_phrases.py 曲.mp3` 找乐句起点，章节首镜对齐乐句（见 shot-script.md）。曲子不够长时，选两首衔接（交叉 3–4 秒），不要把同一首硬接一段。
4. 片名卡落在最后一个乐句上，曲尾自然收。

## 环境声
- **成片默认不用视频模型自带的声音**。实测（`qc.py audio`）：H3 输出的「环境声」大多是 120 Hz 以下的轰鸣加全频段嘶声；保留 20 多段后每个剪点底噪都换一种，用户直接说「很吵」。只用 ASR 查「有没有人说话」不够。
- 用真实录音铺床：Pixabay 音效（可商用）里找雨打瓦、檐滴、风过竹林、湖水、鸟鸣、夜虫、注茶。按镜头类别铺：白棚 → 很轻的风过竹林；临水 → 湖水 + 鸟鸣；雨景 → 雨 + 檐滴；夜景 → 虫鸣；画卷 → 只有音乐。注茶、落杯等动作加一次性音效。
- 每条录音高通 120 Hz、低通 9 kHz，统一到同一电平（约 -38 dBFS RMS），相邻同类镜头连成一段，0.8 秒淡入、1 秒淡出。
- 确需保留某条模型原声时，先用 `qc.py audio` 看低频和嘶声，再核听无人声，才设 `source_audio: "verified_ambience"`。

## 混音（scripts/mix.py）
- cut.py 只出「画面 + 旁白 + 字幕」（`music: []`、`source_audio: "mute"`），mix.py 再铺配乐、环境声、音效。
- 旁白出现时音乐按平滑包络压低约 9 dB（0.6 秒过渡）。**不要用 sidechaincompress**：一说话音乐就被吸下去、停了又弹回来，听着像在呼吸。
- 音乐高通 60 Hz；成片用两遍法测响度后**一次线性调整**到约 -18 LUFS、真峰值 -1.5 dBTP。不要用动态 loudnorm 把整片拉到 -16，那会把安静处的底噪一起抬起来。
- 交付前 `qc.py audio 成片.mp4 --compare 上一版.mp4`，看响度、低频、5 kHz 以上嘶声；声音最终效果要用户听过才算数，交付时说明。

## 字幕（固定样式）
- 白色宋体中文（44px）在上，白色 Baskerville 英文（28px）在下，居中，位于画面下方约 84% 的高度。字下加一层柔和的模糊阴影。
- 画面下方叠一道很淡的暗色渐变，保证白字在浅色画面上也看得清。
- **不要**用黑字加描边，用户觉得很怪。被画面挡住时，再个别处理。
- 小字标签（如「投茶 Add the leaves」）和旁白字幕用同一个样式。

## 片名
- **画卷结构**：在引首素绢上竖排行楷，墨迹先虚后实地渗出来；下方盖一方朱文印，印面随机做一点残缺。配一声空弦和泛音；是否由后期旁白念片名由文稿决定。
- **其他结构**：居中宋体，中文在上、英文在下，淡入。
- 片名和印章都由 cut.py 生成，**不要让 AI 在画面里写字**。
